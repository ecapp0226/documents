# ログインAPI 詳細設計

## データソース
| データソース・対抗先 | テーブル名・API名 | CRUD |
| -------------------- | ----------------- | ---- |
| DynamoDB             | users             | R    |


## 処理詳細
1. リクエストパラメーターのバリデーションチェック
   1. email: 必須、文字列
   2. password: 必須、文字列
   3. バリデーションエラーの場合400エラー(API_ERR001)を返却
2. emailを指定しusersテーブルからデータを取得
   1. Spring SecurityのUserDetailsServiceを実装し、loadUserByUsernameでusersテーブルを検索する
3. 整合性チェック
   1. 2．で取得した結果が空の場合、401エラー(API_LOGIN_ERR001)を返却し、処理を終了
   2. Spring SecurityのBCryptPasswordEncoderを使用し、リクエストボディのpasswordを検証する
   3. 3.2の検証が失敗した場合、401エラー(API_LOGIN_ERR001)を返却
4. JWTの生成
   1. Spring SecurityのJwtEncoderを使用してトークンを生成する
   2. subjectにuser_idを含める
   3. claimsのnameに2.で取得したusers.user_nameを設定
   4. claimsのemailに2.で取得したusers.emailを設定
   5. 有効期限を現在時刻から1時間後の時間に設定する
5. レスポンスの構築
   1. Set-Cookieヘッダーにトークンを設定する
      - key: token
      - value: 4.で生成したJWTトークン
      - HttpOnly: true
      - Secure: true
      - SameSite: Strict
      - Path: /
      - Max-Age: 3600
   2. レスポンスボディにuser_nameを設定する
6. レスポンスの返却
