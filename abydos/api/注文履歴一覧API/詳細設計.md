# 注文履歴一覧API 詳細設計
## データソース
| データソース・対抗先 | テーブル名・API名 | CRUD |
| -------------------- | ----------------- | ---- |
| DynamoDB             | orders            | R    |
| DynamoDB             | sub_orders        | R    |


## 処理詳細
1. AuthorizationHeaderのJWTからログインチェックを実施
   1. 一致しない、期限切れの場合401エラーを返却
2. リクエストパラメータのバリデーションチェック
   1. limit: 数値、1〜100の範囲（未指定時はデフォルト10）
   2. lastOrderId: 数値（任意）
   3. バリデーションエラーの場合400エラー(API_ERR001)を返却
3. 1．からデコードしたuser_idを使い、ordersテーブルからQueryで取得
   1. パーティションキー: user_id
   2. ScanIndexForward: false（降順で取得）
   3. lastOrderIdが指定されている場合、ExclusiveStartKeyに設定する
   4. Limitにリクエストパラメータのlimit値（デフォルト10）を設定する
4. 3．で取得した結果が空の場合、レスポンス項目ordersに空の配列を設定し、7.にスキップ
5. 3.で取得したordersテーブルの各order_idを指定し、sub_ordersテーブルからQueryで取得
   1. 各order_idをパーティションキーとしてQueryを実行する
   2. 取得結果をorder_idをキーとしてグルーピングする
6. 3．と5.で取得した結果を対応するレスポンス項目にマッピングする
   1. 3.の取得結果にLastEvaluatedKeyが存在する場合、レスポンスのlastOrderIdに設定する
   2. 3.で取得したordersの各レコードに対して以下をマッピングする

      | レスポンス項目  | マッピング元                                  |
      | --------------- | --------------------------------------------- |
      | order_id        | orders.order_id                               |
      | created_at      | orders.created_at                             |
      | total           | 対応するsub_ordersのprice * order_numの合計値 |
      | delivery_status | orders.delivery_status                        |

   3. 5.でグルーピングしたsub_ordersの各レコードに対して以下をマッピングし、対応するorderのsub_orders配列に設定する

      | レスポンス項目 | マッピング元           |
      | -------------- | ---------------------- |
      | sub_order_id   | sub_orders.sub_order_id |
      | product_id     | sub_orders.product_id  |
      | product_name   | sub_orders.product_name |
      | shop_id        | sub_orders.shop_id     |
      | price          | sub_orders.price       |
      | order_num      | sub_orders.order_num   |
      | total          | sub_orders.price * sub_orders.order_num |
7. レスポンスの返却
