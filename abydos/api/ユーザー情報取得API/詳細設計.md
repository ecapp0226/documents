# ユーザー情報取得API 詳細設計

## データソース

| データソース・対抗先 | テーブル名・API名 | CRUD |
| -------------------- | ----------------- | ---- |
| JWT claims           | -                 | R    |

## 処理詳細
1. 認証チェック
   1. JwtAuthenticationFilterでCookieからトークンを取得し検証する
   2. トークンが有効な場合、SecurityContextに認証情報をセットする
2. 認証状態の判定
   1. SecurityContextのPrincipalがUserPrincipalのインスタンスでない場合、204 No Contentを返却し、処理を終了
3. ユーザー情報の取得
   1. SecurityContextからUserPrincipal（JWTのclaims由来）を取得する
   2. UserPrincipalからuser_id, user_name, emailを取得する
4. レスポンスのマッピング
   1. user_id: UserPrincipalのユーザーID
   2. user_name: UserPrincipalのユーザー名
   3. email: UserPrincipalのメールアドレス
5. レスポンスの返却（200 OK）

## 備考
- DBアクセスは行わず、JWTのclaimsに含まれる情報のみでレスポンスを生成する
- ユーザー名やメールアドレスを変更した場合は、トークンの再発行が必要
