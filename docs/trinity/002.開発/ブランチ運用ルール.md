# ブランチ運用ルール

Git-flowベース、案件ブランチによる2層feature構造。
デプロイはCodePipelineでブランチ指定により実行。

## ブランチ構成

```
develop（開発統合）
  └── 案件ブランチ（案件スコープ単位）
        └── featureブランチ（個別作業単位）
```

リリース時に`release/YYYYMMDD`を作成。緊急時は`hotfix/xxx`を作成。

## 各ブランチの役割

| ブランチ        | 命名規則           | 用途               |
| --------------- | ------------------ | ------------------ |
| develop         | `develop`          | 開発統合ブランチ   |
| 案件ブランチ    | `project/xxx`      | 案件スコープの管理 |
| featureブランチ | `feature/xxx`      | 案件内の個別作業   |
| releaseブランチ | `release/YYYYMMDD` | リリース成果物     |
| hotfixブランチ  | `hotfix/xxx`       | 緊急修正           |

## フロー

### 通常開発

1. developから案件ブランチを作成
2. 案件ブランチからfeatureブランチを作成
3. featureブランチで開発 → 案件ブランチにマージ
4. 案件が一定完了したタイミングでdevelopにマージし、案件ブランチを凍結

### リリース

1. developから`release/YYYYMMDD`ブランチを作成
2. リリース準備（最終確認・修正）
3. CodePipelineでreleaseブランチを指定してデプロイ

### 緊急修正

1. 該当のdevelopブランチから`hotfix/xxx`ブランチを作成
2. 修正完了後、developにマージし、releaseブランチを切る
3. CodePipelineでデプロイ
