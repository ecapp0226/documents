# 認証仕様

## トークン管理

| 項目                  | 内容                                      |
| --------------------- | ----------------------------------------- |
| 保存場所              | HttpOnly Cookie                           |
| Cookie属性            | HttpOnly; Secure; SameSite=Strict; Path=/ |
| 有効期限              | 1時間（Max-Age=3600）                     |
| リフレッシュトークン※ | なし                                      |
| JSからのアクセス      | 不可（HttpOnly）                          |
  
※現時点では設けていないが、後々の対応で設定も検討

## 認証フロー

### ログイン

1. POST /api/v1/login（email, password）
2. 認証成功 → レスポンスの Set-Cookie でJWTがブラウザに保存される
3. AuthContext の refreshUser を呼び出し（GET /api/v1/me）
4. ユーザー情報を取得してContext更新
5. 遷移元画面（state.from）またはTOP（/）へリダイレクト

### ログアウト

1. Cookie を削除（フロント側で token Cookie を期限切れにする）
2. AuthContext をクリア
3. TOP（/）へリダイレクト

### ページリロード時の復元

1. アプリ初期化時に GET /api/v1/me を呼び出し
2. 200 → ユーザー情報をAuthContextにセット（ログイン済み）
3. 204 → 未認証として扱う（Cookieなし or JWT期限切れ）

## 認証ガード

| 項目             | 内容                                                |
| ---------------- | --------------------------------------------------- |
| 未認証時の動作   | /login へリダイレクト（遷移元を state.from に保持） |
| ログイン後の動作 | state.from があればそこへ戻る、なければ / へ遷移    |

※ 対象画面は各画面設計書の「認証: 必要」を参照

## API認証

| 項目             | 内容                                      |
| ---------------- | ----------------------------------------- |
| トークン送信方法 | Cookie自動送信（credentials: "include"）  |
| 401レスポンス時  | AuthContextクリア → /login へリダイレクト |
