# セキュリティ設計

## 概要

Spring Security 6.5系を使用したステートレスJWT認証を採用。  
セッションを持たず、リクエストごとにCookieからJWTを検証する方式。

## 使用ライブラリ

| ライブラリ            | 用途                     |
| --------------------- | ------------------------ |
| Spring Security 6.5系 | 認証・認可フレームワーク |
| auth0/java-jwt        | JWT生成・検証            |
| BCryptPasswordEncoder | パスワードハッシュ化     |

---

## SecurityFilterChain

`SecurityConfiguration` で定義。全サービス共通で `common` モジュールに配置。

### アクセス制御

| パス                  | 認証                                       |
| --------------------- | ------------------------------------------ |
| `/`                   | 不要                                       |
| `/actuator/health`    | 不要                                       |
| `/api/v1/login`       | 不要                                       |
| `/api/v1/logout`      | 不要                                       |
| `/api/v1/me`          | 不要（内部でJWT検証し未認証時は204を返す） |
| `/api/v1/products/**` | 不要                                       |
| 上記以外              | 必要                                       |

### その他設定

| 項目             | 設定値                      | 理由                                                            |
| ---------------- | --------------------------- | --------------------------------------------------------------- |
| セッション       | STATELESS                   | JWTによるステートレス認証のため                                 |
| CSRF             | 無効                        | Cookie + SameSite=Strict で代替。REST APIのためCSRFトークン不要 |
| フォームログイン | 無効                        | REST APIのため                                                  |
| CORS             | localプロファイル時のみ有効 | 本番はCloudFrontで同一オリジンになるため不要                    |

## JWT

### トークン生成（ログイン時）

`LoginService` で生成。

| claim          | キー    | 内容                     |
| -------------- | ------- | ------------------------ |
| subject        | `sub`   | userId                   |
| メールアドレス | `email` | ユーザーのメールアドレス |
| ユーザー名     | `name`  | ユーザー名               |
| 権限           | `a`     | 権限リスト               |
| 有効期限       | `exp`   | 発行から1時間            |

署名アルゴリズム: **HMAC256**  
シークレットキー: SSM Parameter Storeから環境変数 `JWT_SECRET` で注入

### トークン検証（リクエスト時）

`JwtAuthenticationFilter`（OncePerRequestFilter）がUsernamePasswordAuthenticationFilterの前に実行される。

```
リクエスト
  ↓
JwtAuthenticationFilter
  ├─ CookieからJWT取得
  ├─ JwtDecoder.decode() → HMAC256署名検証 + 有効期限チェック
  ├─ JwtToPrincipalConverter.convert() → UserPrincipal生成
  └─ SecurityContextHolder にセット
  ↓
後続フィルター・Controller
```

トークンが存在しない、または検証失敗の場合は認証情報をセットせずに後続へ委譲（例外をスローしない）。

## Cookie

ログイン成功時に `Set-Cookie` ヘッダーでJWTを返却。

| 属性     | 値                            | 備考                            |
| -------- | ----------------------------- | ------------------------------- |
| 名前     | `token`                       |                                 |
| HttpOnly | true                          | JSからのアクセス不可            |
| Secure   | true（本番） / false（local） | `security.cookie.secure` で制御 |
| SameSite | Strict                        | CSRF対策                        |
| Path     | `/`                           |                                 |
| Max-Age  | 3600（1時間）                 | JWTの有効期限と同一             |

ログアウト時は同名Cookieを `Max-Age=0` で上書きして削除。

---

## パスワード

- ハッシュアルゴリズム: **BCrypt**（`BCryptPasswordEncoder`）
- DynamoDBの `users` テーブルに `passwordHash` として保存
- ログイン時に `passwordEncoder.matches()` で検証

---

## 認証エラー時のレスポンス

認証が必要なエンドポイントへ未認証でアクセスした場合、`CustomAuthenticationEntryPoint` が処理する。

| 項目           | 内容                                       |
| -------------- | ------------------------------------------ |
| HTTPステータス | 401                                        |
| エラーコード   | `API_ERR003`                               |
| レスポンス形式 | `{"code": "API_ERR003", "message": "..."}` |

## 関連クラス

| クラス                             | 役割                                                     |
| ---------------------------------- | -------------------------------------------------------- |
| `SecurityConfiguration`            | FilterChain定義、アクセス制御、AuthenticationManager設定 |
| `JwtAuthenticationFilter`          | リクエストごとのJWT検証・SecurityContextへのセット       |
| `JwtDecoder`                       | HMAC256署名検証・有効期限チェック                        |
| `JwtToPrincipalConverter`          | DecodedJWT → UserPrincipal 変換                          |
| `UserPrincipal`                    | SecurityContext内の認証済みユーザー情報                  |
| `UserPrincipalAuthenticationToken` | SecurityContextに格納する認証トークン                    |
| `CustomUserDetailService`          | DynamoDBからemailでユーザーを検索しUserDetailsを返す     |
| `CustomAuthenticationEntryPoint`   | 未認証アクセス時の401レスポンス返却                      |
| `CorsConfig`                       | localプロファイル時のCORS設定                            |
| `JwtProperties`                    | `security.jwt.secret` のバインド                         |
| `CookieProperties`                 | `security.cookie.secure / sameSite` のバインド           |
| `SecurityUtils`                    | SecurityContextからuserIdを取得するユーティリティ        |
