# 注文確定API 詳細設計
## データソース
| データソース・対抗先 | テーブル名・API名 | CRUD |
| -------------------- | ----------------- | ---- |
| DynamoDB             | orders            | C    |
| DynamoDB             | order_details     | C    |
| DynamoDB             | products          | RU   |
| DynamoDB             | sequences         | U    |


## 処理詳細
1. AuthorizationHeaderのJWTからログインチェックを実施
   1. 一致しない、期限切れの場合401エラーを返却
2. リクエストパラメータのバリデーションチェック
   1. products: 必須、配列が1件以上であること
   2. products[].product_id: 必須、数値
   3. products[].quantity: 必須、数値、1以上
   4. バリデーションエラーの場合400エラー(API_ERR001)を返却
3. リクエストボディの注文可否のチェック
   1. リクエストのproducts配列を同一product_idで集約し、数量(quantity)を合算する
   2. productsテーブルから集約後のproduct_idをキーにしてBatchGetItemで取得
   3. 商品が存在しない場合、400エラー(API_ORDER_ERR001)を返却
   4. 商品ステータスが購入不可の場合、400エラー(API_ORDER_ERR002)を返却
   5. 在庫数 < 集約後の注文数量の場合、400エラー(API_ORDER_ERR003)を返却
4. 注文履歴テーブルの登録
   - TransactWriteItemsを使用し、以下の操作を1トランザクションで実行する
   - いずれか1つでも失敗した場合、全操作をロールバックする
   1. ordersテーブルに登録する（Put）
      1. order_id: sequencesテーブルから採番（sequence_name="order_id"でUpdateItem ADD、ReturnValues=UPDATED_NEW）
      2. user_id: JWTからデコードした値
      3. create_at: 現在時刻(UnixTimestampミリ秒)
   2. order_detailsテーブルに登録する（Put）
      1. リクエストのproducts配列の件数分レコードを作成
      2. detail_id: sequencesテーブルから採番（sequence_name="detail_id"でUpdateItem ADD、ReturnValues=UPDATED_NEW。件数分まとめてインクリメントし連番を割り当てる）
      3. order_id: 4.1で登録したorder_id
      4. product_id: リクエストの値
      5. product_name: 3.2で取得した商品名
      6. shop_id: 3.2で取得したshop_id
      7. price: 3.2で取得した単価
      8. order_num: リクエストのquantity
      9. delivery_status: 初期ステータスを設定
   3. productsテーブルの在庫を更新する（Update）
      1. 各商品の在庫数から注文数量(quantity)を減算する
      2. ConditionExpressionで在庫数 >= quantityを指定
   - 注意事項:
     - 1トランザクションあたり100アイテム上限のため、products配列の件数に応じた上限チェックを実施すること
     - 同一商品が重複する場合は事前に数量を集約してからトランザクションを実行すること
5. レスポンスの返却
